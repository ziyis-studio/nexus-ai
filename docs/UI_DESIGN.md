# Nexus interface system

The 2026-10-27 redesign follows the official [shadcn skill](https://ui.shadcn.com/docs/skills), installed from `shadcn-ui/ui/skills/shadcn` at revision `8f04138777c1b6996e709993362a7b0a12888ecf`. The application retains the PRD's Nuxt 4 / Vue architecture and uses the compatible [shadcn-vue](https://www.shadcn-vue.com/docs/installation/nuxt) implementation with Reka primitives and the Nova style.

## Foundation

- `apps/web/components.json` records the registry, style, paths and icon library.
- Components were installed as source through the shadcn-vue CLI. Reusable variants live in `components/ui`; page classes control layout. Keep controls, focus rings and overlay behavior in the primitives.
- Semantic OKLCH tokens in `assets/main.css` define light/dark surfaces, primary actions, status colors and sidebar colors. Self-hosted Inter is pinned through Fontsource; no external font request is needed.
- Use FieldGroup/Field/FieldLabel for forms; Badge variants for status; Card composition for surfaces; Alert/Empty/Skeleton for feedback; Dialog/Sheet/AlertDialog for focused tasks and final decisions.
- Use the configured Lucide icon objects directly, with icon placement attributes in controls. Avoid string-based icon lookup.
- Preserve the Nuxt integration module and app-level TooltipProvider. Routed page content needs a provider above NuxtLayout/NuxtPage.

## Workflows

- Login has named fields, password visibility, clear failure recovery and disabled submission while pending.
- Workspace cards show authorized organizations and roles. The sidebar switches directly between current memberships, while navigation refreshes trusted membership state.
- The sidebar supports a mobile sheet and desktop collapse; quick navigation uses Ctrl/Cmd + K and keyboard selection. Appearance is stored per device as light, dark or system.
- Tickets prioritize the queue, debounced search, status/priority filters, recoverable empty/error states and honest page counts. Cursor navigation remains server-backed. No decorative metrics imply global totals.
- Ticket detail places customer context beside the draft. Response/insight tabs, persistent cited knowledge, copy, progress, retry, review and history stay near the decision. Rejecting a draft asks for confirmation because that decision is final.
- Creating/editing uses labelled dialogs with focus restoration and preserved input on submission errors. Pending saves prevent accidental dismissal.
- Knowledge cards distinguish document type and active/archived state. Admins can edit; other roles get a reader.
- Execution history links to the associated ticket and offers an accessible sheet with timing, attempts and safe failure information.
- Organization settings separate general details, admin membership/audit views and per-device appearance.

## Boundaries

Membership remains authoritative on the server/database. No business call uses a service-role shortcut. Tenant changes remount page-local data and tear down run watchers. Analysis idempotency, durable progress reconciliation, final review and the rule that approval never sends a message remain intact. This UI change does not alter the hosted schema or constitute an application deployment.

## Verification and evidence

The browser suite covers the original workflows plus quick navigation/theme persistence, search recovery and focus restoration, ticket editing/final rejection, a 320px reduced-motion view, and automated WCAG A/AA checks on core screens. Automated accessibility checks complement keyboard and visual review; they are not a complete accessibility certification.

The updated screenshots and walkthrough are generated by `scripts/capture-demo.mjs`. It targets only the loopback QA environment and creates clearly synthetic sample records. The local PostgreSQL/PostgREST boundary is real, while Auth, Redis transport and model output use the documented preview fixtures. This evidence does not establish cloud sign-in or live OpenAI inference.
